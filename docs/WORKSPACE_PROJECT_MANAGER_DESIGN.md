# Workspace Project Manager 设计

> 状态：设计草案，尚未实现。

## 目标

用户可为一个 Bridge workspace 指定一个 Agent 作为 Project Manager（PM）。PM 接入 workspace 时先读取项目说明并建立工程概览；之后用户可在 VS Code 对话框中询问工程、设计、代码位置、任务失败原因和改进建议。PM 在任务失败或达到两小时运行阈值时也会主动分析，并可基于该 workspace 的任务摘要归纳反复出现的问题。

PM 提供诊断和建议，不代替用户或任务 Reviewer 作决定，也不执行、返修、批准、合并或重新派发任务。

## 复用与边界

- Workspace 用现有 `workspace.id` 标识，PM 配置按 workspace 持久化；不按窗口或当前活动文件夹临时绑定。
- 已完成、失败和检视失败任务复用 `thread.finalSummary`。查找和汇总只限定在同一 workspace。
- 正在运行的任务没有终态摘要。两小时提醒使用由账本派生的限量快照：任务 brief、轮次、活跃运行时间、最近进度、assessment、interruption 和输出尾部摘要；不得伪造或写入 `finalSummary`。
- 运行时间使用与任务超时相同的单调活跃时间口径，扣除主机休眠/挂起时间。默认阈值为 120 分钟。若任务因默认两小时总超时而终止，则以超时失败事件触发一次分析；若用户将任务超时配置调长，则在达到 PM 阈值时对仍运行任务发一次提醒，任务继续执行。
- PM 使用 workspace 专属原生会话，与任务的 reviewer/developer 会话及角色锁完全分离。PM 不取得任何 task role lease，也不阻塞该 workspace 的任务调度。

## 配置与存储

每个 workspace 有独立配置：

```ts
interface WorkspaceProjectManagerConfig {
  enabled: boolean;
  agent: AgentId;
  configuredAt: string;
}
```

用户通过“设置 Workspace PM”命令选择 Agent，并可在设置中关闭或更换。模型遵循所选 Agent 的 `initiatorModels.*` 配置；PM 不自行选择非默认模型，也不请求模型切换。Agent 不可用或启动失败时向用户展示原因，不自动换 Agent。

配置与会话元数据放在 `~/.agent-mesh-bridge/workspace-pm/<workspaceId>/`，不修改 workspace 根目录或任务 worktree。会话元数据至少记录 Agent、native session ID、首次/最近使用时间和 schema 版本。聊天记录只存用户消息、PM 最终答复和时间戳；不持久化隐藏推理。

### PM 接入与工程概览

首次设置 PM 或更换 PM Agent 时，宿主启动该 workspace 的 PM 初始化轮次。初始化先读取并遵循 workspace 根目录及相关子目录中的 `AGENT.md`、`AGENTS.md`；存在多个文件时遵守目录层级，分析具体文件前也读取其所在目录适用的指令。随后读取项目入口资料（如 `README*`、`DESIGN.md`、`docs/`、包/构建/测试清单），并通过只读目录树、代码搜索和文件读取形成工程概览：主要模块、入口、关键数据流、配置、测试/构建方式及已知未完成项。仓库没有这些文件时如实标记，不编造。

不把整个仓库一次性塞进 prompt。初始化写入 PM 自己的 workspace 原生会话，保存一份带 Git HEAD、项目说明文件指纹和生成时间的简短工程地图；PM 后续回答可按需继续搜索和读取具体文件。用户可在面板中执行“刷新工程概览”；检测到 HEAD 或项目说明变化时提示刷新，不能把旧地图冒充最新状态。更换 Agent 或清除 PM 会话后重新初始化。

## 触发与调度

`WorkspaceProjectManagerService` 由扩展宿主运行，订阅 TaskStore 变化并定期检查长任务：

1. 对 `failed` 和 `review_failed` 的终态变化触发失败分析。用户主动暂停、停止或删除不算失败，不触发。
2. 对运行中任务，在活跃运行时间达到阈值时触发一次长任务分析；若恰好由超时结束，则合并为同一条诊断，不能重复提醒。
3. 每个触发以 `(workspaceId, threadId, round, triggerKind)` 去重，结果及通知状态持久化；宿主重启后不重复发送已完成的诊断。
4. 任务列表或摘要变化可供 PM 后续回答使用，但不自动因每个成功任务都弹窗。用户通过 PM 对话显式请求 workspace 汇总，避免通知轰炸。
5. 同一 workspace 同时只运行一个 PM 请求；不同 workspace 的 PM 可以并行。PM 请求有硬超时，超时失败可由用户在对话框重试。

触发诊断先显示非模态 VS Code 通知，带“查看建议”入口；只有用户打开后才显示聊天面板。长任务通知不打断正在编辑的工作。失败触发若已打开 PM 面板，则在面板内追加新诊断，不再弹第二个面板。

## PM 输入与回答

宿主为每次分析生成有界、结构化的上下文包：

- workspace 名称与 ID；
- 触发任务的 `finalSummary`，若为活动任务则使用上文定义的只读实时快照；
- 用户要求 workspace 级归纳时，最近 20 个终态任务的 `finalSummary`，按时间倒序，并附统计窗口和被排除/归档数量；
- 可选的相关轮次 `assessment`、中断原因和错误摘要。

PM 可按用户问题调用桥接提供的只读工程查询能力：列出 workspace 相对路径、搜索文本、读取指定文件及查看 Git 状态/差异摘要。所有路径必须限制在绑定 workspace 内，解析符号链接后再次校验边界；拒绝读取凭据、密钥、`.env`、私钥、Git 内部对象和超出大小上限的文件。查询不执行 shell、不写文件、不访问任务 worktree；PM 不能自行读取原始 stdio 日志或完整轮次输出，用户可通过证据链接在 VS Code 打开日志。

上下文优先使用项目说明、源码和任务摘要。原始 stdio 日志、完整轮次输出、API key、环境变量及会话 transcript 不自动发送给 PM。所有读取结果遵循用户所选 Agent 的模型配置和现有模型同意规则；PM 只得到明确查询返回的文件片段，不做隐式全仓上传。

提示 PM 将回答分成：观察到的证据、可能原因（标记推测）、建议的下一步、需要用户决定的问题。每条共性结论应标明样本数和任务 ID，避免把单个案例说成普遍规律。PM 输出是建议，不直接更改任务状态或触发工具动作。

PM 运行环境使用 `MESH_WORKSPACE_PM=1`。MCP server 在该模式下只开放该 workspace 的只读工程查询和 PM 对话所需能力，隐藏并拒绝任务派发、返修、审批、暂停/删除和 MR 控制工具。启动配置不得继承 worker 的 `skip-danger` 写权限；还必须关闭 Agent CLI 自带的写文件和任意 shell 工具。若某 Agent CLI 无法可靠禁用这些能力，则该 Agent 的 PM 只能使用宿主注入的工程索引与受限查询结果，不能启动带原生工具权限的会话。PM 的权限边界是 workspace 内只读；任何修改建议由用户决定后再通过正常开发/任务流程执行。

## 对话 UI

新增 Workspace PM Webview，沿用现有 `TaskDetailPanel` 的消息通信和安全渲染模式：

- 可从 workspace 选择器/命令面板打开，标题展示 workspace 与所选 PM Agent；
- 初次打开前显示工程概览初始化状态；面板可查看概览、刷新概览和读取状态（更新时间、HEAD、扫描范围）；
- 展示自动诊断卡片、触发原因、证据链接（任务详情/相关轮次日志）和 PM 建议；
- 输入框允许用户自由提问工程相关问题、任务问题或方案意见；后续消息沿用同一 workspace PM native session。超出已读证据时，PM 可在只读边界内继续查找；仍无证据时明确说明不确定性；
- 提供“分析最近任务”操作，显式请求跨任务共性分析；
- 提供“重试本次分析”和“清除 PM 会话”操作；清除只移除 PM 原生会话与 PM 聊天记录，不触碰任务及 legacy caller 会话。

Agent CLI 启动、会话恢复和输出提取沿用现有 agent adapter 能力。只有退出码为 0 且提取到实际最终文本才保存为成功答复；空输出、CLI 失败或中断展示为明确错误，保留用户消息供重试。

## 最小实施阶段

1. Workspace 级 PM 配置、初始化读取工程说明/建立概览、只读文件查询、PM 独立会话及聊天面板。
2. 失败/检视失败和两小时阈值触发、去重、主动诊断卡片。
3. “分析最近任务”读取最多 20 个终态摘要，给出带样本数的共性建议。

首版不做自动修复、自动重派、可配置触发规则、原始日志检索或跨 workspace 分析。工程概览是可逐步补全的导航和证据索引，不声称一次扫描后模型就能永久掌握仓库每个细节。

## 验收条件

- 两个 workspace 可配置不同 PM Agent；切换默认 workspace 不会串用配置或会话。
- 设置或更换 PM 时先读取适用的 `AGENT.md` / `AGENTS.md` 和项目入口文档；缺失文件如实处理。
- PM 可通过受限只读查询回答代码、架构、构建测试和项目状态问题；越界路径、敏感文件和写入操作均被拒绝。
- PM Agent 无法通过 CLI 原生工具绕过只读边界；无法证明只读能力的适配器会降级为仅使用宿主提供的资料。
- 刷新概览后记录新的 HEAD 和说明文件指纹；旧概览不会被标记成当前版本。
- worker 失败、review_failed、两小时阈值各最多触发一次；用户 pause/stop/delete 不触发；默认两小时超时不会生成两次诊断。
- 两小时按活跃时间计算，宿主睡眠不推进阈值；任务运行中的实时快照不写入终态摘要。
- 活动/归档任务的终态摘要均可用于 workspace 汇总；缺少摘要的旧任务明确计为不可用，不猜测内容。
- PM 聊天恢复同一 PM 原生会话，且不会申请 task role lock 或影响任务调度。
- PM 无法调用任务变更控制面；只将有界任务摘要/诊断包及用户明确查询的文件片段交给 Agent。
- Agent 退出非零、空输出、超时及 workspace 未配置 PM 时 UI 均有清晰状态，且不会静默切换 Agent 或模型。

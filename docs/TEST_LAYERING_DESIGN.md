# 测试分层与性能验收设计

日期：2026-11-18。状态：设计完成，等待实现与实测验收。

目标是在保留现有行为覆盖和真实并发安全验证的前提下，减少重复 Git 准备、锁辅助进程启动和持久化写入。开发、检视、合入共用同一分层规则。实现交给 Antigravity；只有完整测试集实测有稳定收益，检视方才尝试合入。

## 2. 分层边界

按被验证的行为归层。一个用例只归一个主层；跨层承诺用覆盖映射说明，不能重复计数。混合文件优先按下表拆开，不为迁移而重命名全部测试。

| 层 | 验证对象 | 允许替身 | 必须保留的真实证据 |
| --- | --- | --- | --- |
| policy 策略层 | 状态转换、结果分类、退避次数、活动预算、quota、决策恢复、淘汰候选计算 | 可控时钟、runner、进程身份查询、存储和锁边界 | 调用真实业务策略，断言完整前后状态及禁止的副作用 |
| boundary 边界层 | TaskStore 序列化、重载、CAS、revision、身份验证；Git ref、stash 等单一事务阶段 | 不相关的 runner、验证命令、上层调度 | 被测存储、Git 或 OS 边界必须真实执行 |
| integration 集成层 | develop→review→merge 交接、独占执行、跨进程竞争、取消、崩溃恢复、脏工作区保护 | 无关外部 Agent 可用受控子进程，避免调用付费模型 | 真实进程、锁、账本和所需 Git 流程；恢复后检查耐久结果 |

策略层不能用只返回期望结果的假控制器替代业务实现。边界层与集成层不能全局替换 `transitionExecution`、CAS 或 OS 锁后声称已经验证并发安全。

既有 VSIX Extension Host smoke 维持独立命令，用于打包/安装验证；它不在现有 `npm test` 基线内，不把两种范围混入同一个收益数字。

## 3. 本次实施范围

### 3.1 统一生命周期

先逐条分类 `unified-execution-lifecycle.test.ts`，再分开纯策略和真实持久化/进程用例。优先复用已有的时钟、runner 与 platform provider，必要时只添加最小的依赖入口；保持生产默认路径及锁协议不变，不建设新的通用测试框架。

重试预算使用虚拟时间：验证 5 秒、30 秒边界及最多额外两次自动重试，quota 不耗次数、手动 retry 新 generation、resume 保留预算。保留时间尚未到时不得执行的负向断言，不能仅清空 `notBefore` 就宣称覆盖退避。

活动预算与挂起扣除、空输出失败、流间隔 warning、超时/不确定工作禁止重放、跨阶段决策恢复均保留原行为断言。纯策略用例不得为了这些分支反复启动 PowerShell 锁进程。

真实边界至少覆盖：跨 TaskStore 实例及跨进程 CAS 冲突、同 thread 唯一运行权、旧 generation 回调拒绝、PID 相同但 birthId 不同、缺失身份与退出未确认时不得提前交接、暂停/删除取消及进程退出后释放、重载后的恢复判定。真正的跨进程不变量至少有跨进程用例，不能全部降为同进程 mock。

### 3.2 Git 事务准备

复用现有 seed/fixture helper。每个用例使用独立可写仓库；不可共享活动 worktree、refs、index 或可写 stash。只读 seed 仅用于复制初始状态，不把一个用例的修改带入另一个用例。

把只检查预算、时间、候选选择的用例降到策略层；把只检查一个 stash/ref 阶段的用例改为直接准备合法阶段前置条件，调用真实被测阶段。保留代表性的完整事务，以及 dirty target、stash 冲突、ref CAS 失败、验证失败回滚、各耐久崩溃窗口的真实恢复覆盖。已有虚拟时间 stash 锁重试仍须执行真实失败路径并验证重试次数与锁保留。

只拆分实测形成长尾的文件，依据文件起止记录调度长任务。禁止把每个测试机械拆成独立文件，避免新增进程启动成本。

### 3.3 账本容量

容量测试通过合法持久化格式预置接近或达到边界的安全终态记录，再走真实公开 upsert 与重载验证越界淘汰。保留上限 1,000、最旧安全记录被淘汰、最新记录保留、活跃/未交付成果不可淘汰、无安全候选拒绝等边界。

原有 1,050 次 upsert 的淘汰顺序断言通过批量预置加少量真实越界写入表达；不能只改成断言数组长度，也不能依赖私有内存字段伪造持久化成功。

## 4. 执行入口与覆盖清单

沿用 Node 内建 test runner 和 `scripts/test.cjs`。默认 `npm test` 仍执行全部既有测试及新增必要用例，保持四个 worker 的统一上限；不要按三个层串行重跑三个四并发池，也不要并行开启三个池造成十二并发。

提供轻量的按层选择入口供开发自检，默认入口始终是三层并集。沿用项目命名和脚本风格，只增加实际需要的参数或命令。保留失败退出码；测试发现须能识别漏归类文件，防止移动后静默漏测。基准每轮清理编译测试输出再编译，避免旧 `.test.js` 残留重复运行。

交付覆盖清单：原文件和测试名称、原验证承诺、新文件/名称、所属层、仍需真实执行的依赖。680 项只是历史盘点；若派发基线已变化，先重新盘点。迁移后逐条有去向，合并重复用例需列明保留的断言及理由，不能靠减少验收场景制造收益。

## 5. 测量与计算

在同一机器、同一 Node/Git/PowerShell 版本、同一 pinned 基线及其实现候选上比较。两者都使用独立工作树、相同依赖锁定版本、四并发和相同测试发现范围。记录提交、版本、命令、覆盖数、退出码、机器负载与同时运行的任务；不擅自暂停其他任务。

先分别预热一次，再交错执行至少三组完整对照，例如 A/B、B/A、A/B。A 为派发基线，B 为候选。冷启动额外单列，不能一边使用热缓存、一边使用冷缓存。若其他重任务或系统休眠污染一组，记录原因并重测该组，不能挑选最快结果。

每轮记录：完整测试墙钟时间、编译时间、分层用例数及各层独立运行耗时、全量运行中的文件起止时间、Git 命令次数、锁辅助进程启动次数、实际账本写入次数。分层独立运行至少各测一次，解释结构变化；独立层耗时与文件工作时长都不能相加代替完整运行墙钟时间。

计数可复用已有 profiling/preload 做外部测量，不给生产添加常驻遥测。计数采样和计时需区分：若 instrumentation 影响耗时，A/B 都启用同样的采样，并另做未采样的正式计时。多重嵌套区间单列，不把 CAS 与其内部锁时间重复计入。

计算并报告：

- 全量收益 = `(median(A) - median(B)) / median(A)`。
- 每对绝对节省 = `A[i] - B[i]`，报告三对原值、范围及中位数。
- 各层报告用例数、独立耗时、Git/锁/写入次数变化；说明成本减少来自哪些依赖边界。
- 长尾根据真实文件起止时间与 worker 空闲间隙判断，不能仅凭文件名或工作时长推断已消除。

## 6. 验收与合入条件

采用以下实际收益门槛：三组完整对照均变快，全量中位数同时下降至少 10% 和 30 秒，且中位数差大于 A、B 各自三次运行极差的较大值。该门槛用于排除之前约 3 秒级别的波动，不是已取得的收益承诺。若高波动导致不满足，增加有记录的对照或报告证据不足，不放宽覆盖与安全条件。

必须同时满足：编译通过；全部测试通过且无新增 skip/todo/仅按环境绕过；覆盖清单完整；真实跨进程及恢复边界保留；生产锁/生命周期语义无变化；测试后无遗留辅助进程。清理受阻需报告具体进程/路径，不能误杀其他任务。

开发者只交付实现、原始日志、机器可读汇总和收益结论，不提交、不推送、不自审、不发起合入。检视方检查 diff 与覆盖映射，复跑必要安全用例和至少一组完整 A/B；若复验矛盾，继续验证而非批准。

达到门槛后才批准并尝试经现有全局合入锁向最新 master 集成，验证合成结果及真实目标提交。master 变化后重跑相关验证，若变化影响基准须更新对照。未达门槛或覆盖不足时保留工作树和报告，明确暂不合入；不得为达标修改基线、删除慢测或扩大生产重构。

## 7. 交付物

1. 最小代码变更：分层测试、必要 fixture/注入入口、执行选择与覆盖检查。
2. 原用例到新分层的映射，以及真实边界保留列表。
3. `benchmark.json` 与原始日志：基线/候选身份、三组完整数据、层数据、依赖次数、计算结果、污染与清理说明。
4. 检视结论：是否满足收益门槛、是否保留覆盖、是否建议尝试合入。尚未测量的项目明确留空，不估造数字。
